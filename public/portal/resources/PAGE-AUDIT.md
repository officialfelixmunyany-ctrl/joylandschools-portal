## 1. Visual Inventory

The page is a vanilla ES-module single-page app mounted into:

- `#app-shell`
- `main#main`
- `#modal-root`
- `#toast-root`

`index.html` contains no visible app content except the skip link. Everything inside `#main` is generated by `Home(state)` or alternate route renderers in `src/main.js`.

- Creates tenant settings.
- Creates academic session.
- Creates owner admin code like `CODE-ADM-0001`.
- May auto-approve depending on `AUTO_APPROVE_SCHOOLS`.
- Sends email if SMTP is configured and owner email exists.

## 4. Animation and Motion Audit

Visible current resource page motion:

- Button hover:
  - `.primary-btn`, `.login-btn`, `.open-resource` move by `translate(-1px, -1px)`.
  - no explicit transition set on these buttons, so movement is immediate.
- Catalog menu hover/open:
  - background changes.
  - transform `translate(-1px, -1px)`.
  - shadow increases.
  - no explicit transition.
- Center blocks/rails/search hover:
  - shadow increases from `3px 4px` to `4px 5px`.
  - no explicit transition.
- Resource card hover:
  - old card component only.
  - transform `translate(-2px, -2px)`.
  - shadow `7px 7px 0`.
  - transition `140ms ease`.
- Level tile hover:
  - old/unused visible route styles.
  - translateY `-2px`.
  - transition `160ms ease`.

Loading animation:

- Keyframes: `shimmer`.
- Duration: `1.4s`.
- Infinite.
- Used by `.skeleton-card` and `.skeleton-row`.
- Background moves from `100% 0` to `0 0`.

Modal:

- Backdrop appears instantly.
- Backdrop blur `8px`.
- Modal centered by transform.
- No entrance animation.

Toast:

- Appears instantly.
- Removed after `2800ms`.
- No fade/slide animation.

Route motion:

- Resource app does not animate hash routes.
- Connected `/schools` page does animate views:
  - `view-out .16s ease`.
  - `view-in .24s cubic-bezier(.2,.8,.2,1)`.
  - Uses View Transition API if available.
  - Has `prefers-reduced-motion` fallback.

Scroll behavior:

- `html { scroll-behavior: smooth; }`.
- Category changes scroll `#center` into view smoothly.
- Search shortcut scrolls input into view smoothly.

## 7. Interaction Audit

Global keyboard:

- `Tab` switches `document.documentElement.dataset.input` to `keyboard`.
- Pointer down switches input mode to `pointer`.
- `Escape` closes menus and modal.
- `/` focuses the search input unless typing in input/textarea/select/contenteditable.

Menu interactions:

- Clicking `[data-menu]` toggles parent `.open`.
- Only one menu opens at a time.
- Clicking outside `.menu` and `.resource-catalog` closes menus.
- Clicking a category link calls `applyCategory`.

Category behavior:

- Sets filters:
  - level.
  - type.
  - audience.
  - optional query.
- Resets route hash back to `#/` if needed.
- Updates search input value to query.
- Scrolls `#center` into view.

Search behavior:

- Typing into `#home-search-input` triggers debounced search after `260ms`.
- Submitting form applies search immediately.
- Free-text search clears category filters to all.
- Search route does not change hash.

Reset behavior:

- `[data-action="reset-filters"]` resets filters.
- Clears search input.
- Scrolls center to top.

Resource open behavior:

- `[data-action="open"]` fetches resource detail.
- Public resource opens reader modal.
- Protected resource opens access modal.
- Opening public resource marks it read in localStorage.
- `Open file` click tracks download via POST.

Save behavior:

- `ResourceCard` has save buttons.
- Current result rows do not show save buttons.
- Modal still has save resource action.
- Saved IDs stored in localStorage.

School finder:

- Route `#/school-login`.
- Form submit calls `/api/public/schools`.
- Results are rendered inline.
- Input is focused and selected when panel binds.

Create school:

- Route `#/create-school`.
- School code input uppercases.
- Submit calls `/api/public/register-school`.
- Success message varies by approval status and email sent flag.
- Form resets on success.

Contribution:

- Opens modal.
- File, grade, subject required.
- Max file size `25MB`.
- Posts Data URL.
- Success replaces modal with received/thanks modal.

Accessibility:

- Skip link present.
- Main has `tabindex="-1"`.
- Modal has `role="dialog"` and `aria-modal="true"`.
- School result area uses `aria-live="polite"`.
- Toast root has `aria-live="polite"` and `aria-atomic="true"`.
- Dropdown buttons use `aria-haspopup` and update `aria-expanded`.

Accessibility concerns:

- Modal focus is not trapped.
- Close button text is `x`, not visually ideal, though aria-label exists.
- Many buttons remove focus outlines globally; keyboard focus visibility is restored only for `.resource-file-link`.
- Current `ResourceListItem` is a button, not an anchor; files are opened through modal rather than direct link.

## 8. Data and Logic Audit

State store:

- Filters in `localStorage` key `civicom.library.filters`.
- Saved IDs in `civicom.library.saved`.
- Read IDs in `civicom.library.reads`.
- Store state:
  - `filters`
  - `resources`
  - `savedIds`
  - `readIds`
  - `loading`
  - `error`

Default filters:

- query `''`
- audience `all`
- level `all`
- type `all`
- subject `all`
- sort `relevance`

Resource fetch:

- Endpoint: `GET /api/portal/resources`.
- Params built from normalized filters:
  - `q`
  - `type`
  - `subject`
  - `level`
  - `grade` if mapped
  - `audience`
  - `sort`
  - `published`
- Response cache TTL: `90,000ms`.
- In-flight request de-duplication uses a Map.
- Session info fetched from `/api/auth/me`.
- If API fails and `useMockFallback` is true, bundled mock data is filtered locally.

Resource normalization:

- Type aliases normalize to kebab-case.
- Level aliases map API/server values to frontend values.
- Audience normalizes to array.
- File URL resolves to:
  - external URL unchanged.
  - `/uploads/...` unchanged.
  - relative filename becomes `/uploads/resources/<encoded>`.
- Visibility determines `protected`.
- Access label generated from visibility/premium.

Filtering:

- Query matches title, summary, grade, subject, year, type, format.
- Audience matches selected audience or `everyone`.
- Level uses direct match or `LEVEL_GROUPS`.
- Type exact match.
- Subject exact case-insensitive match.
- Sort:
  - `newest`.
  - `popular` or `downloads`.

Backend resource endpoint:

- Requires published and status published.
- Public users see only public visibility.
- Filters type, subject, grade, level, audience, visibility, featured, q.
- Hides TVET/college/diploma/certificate/university terms from public library.
- Returns up to 200 resources.

Observed API:

- `/api/portal/resources?type=scheme&audience=teacher` returns 4 public scheme resources.
- They are DOCX files grouped by grade in UI.

Service worker:

- Cache name: `civicom-learning-portal-v36`.
- Core cached:
  - `./`
  - `./index.html`
  - `./assets/styles.css`
  - `./src/main.js`
- Runtime caches GET responses.
- Offline fallback to `index.html`.

## 13. Final Master Report

The page is a single-page public education resource catalog implemented with vanilla JavaScript modules and one global CSS file. Its default screen is a three-column school-resource directory: a top taxonomy catalog, left year shortcuts, center search and category maps, and right school/contribution/quick-action rails.

The visual system is currently best described as educational neo-brutalism: hard navy borders, small radii, offset shadows, dense information panels, and an education-coded palette of academy blue, school green, achievement gold, and warm ivory. This is now much closer to a standard school/education interface than the earlier decorative pink/peach/lavender palette.

The strongest parts of the page are:

- clear resource taxonomy,
- strong visual grouping,
- compact result rows,
- school/login separation,
- live API integration,
- review-first contribution flow,
- service worker cache,
- local saved/read state.

The main cleanup opportunities are:

- update saved copy or expose save affordance in result rows,
- remove stale CSS/components or document them as legacy,
- improve modal focus trapping,
- restore keyboard focus outlines more broadly,
- update README to match the current route/component reality,
- optionally load Inter explicitly if the typeface is intended.

Overall, the page now reads as an operational school resource catalog rather than a decorative landing page. The current palette and panel system are suitable for an education product: blue for trust and academics, green for school/growth, gold for contribution/achievement, ivory for reading, and dark navy for structure.
